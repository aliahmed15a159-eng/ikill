# iKILL — تطبيق Flutter أصلي لـ Android وiOS

مشروع منفصل عن مستودع الموقع، بواجهات Flutter وDart فعلية. **لا يحتوي على WebView أو صفحات HTML للتشغيل.** الصور والأيقونات ومحتوى الصفحات والترجمات نُقلت من الموقع، وأعيد تنظيم الواجهات لتناسب الموبايل بـ Material 3، مع الحفاظ على الأخضر والأبيض والخلفية البيئية والشعار.

## محتويات التسليم

- `lib/`: الواجهات، نموذج الطلبات، الاتصال بقاعدة البيانات، ولوحة الإدارة.
- `android/`: مشروع Android بـ Kotlin، وإذن الإنترنت وأيقونات iKILL وGradle wrapper.
- `ios/`: مشروع Xcode بـ Swift، وأيقونات iKILL وPodfile (iOS 13 فأحدث).
- `assets/data/`: المحتوى المستخرج من صفحات الموقع وترجماته والخدمات الست.
- `assets/images/`: صور الموقع وشعارات الشركاء وأيقونات الآفات الأصلية.
- `test/`: اختبارات محتوى وواجهات مكتوبة، لم تُشغّل في بيئة التسليم.
- `tool/configure_firebase.py`: إعداد اتصال Firebase الأصلي من ملفات التطبيقين الرسمية.
- `.github/workflows/verify.yml`: فحص وبناء Android وiOS عند رفع **هذا المشروع المنفصل** إلى مستودع تختاره؛ لم يُشغّل بعد.
- `source-manifest.json`: بصمات SHA-256 لملفات الموقع وقت النسخ.
- `VERIFICATION.md`: ما تم فحصه فعلياً وحدود التسليم.

## المتطلبات

Flutter **3.29.3** وDart المرفق به، Android SDK وJDK 17. لبناء iOS يلزم **macOS وXcode وCocoaPods**. يمكن تجربة المحتوى والواجهات من غير إعداد Firebase؛ ستظهر رسالة واضحة وتتوقف أزرار الإرسال والإدارة بدلاً من إظهار نجاح وهمي.

```sh
flutter doctor
flutter pub get
flutter run
```

لا توجد ملفات بناء ضخمة أو SDK أو أسرار حسابات داخل التسليم. يتطلب تنزيل الحزم وأدوات المنصات اتصال إنترنت.

## تفعيل Firebase للموبايل — خطوة مطلوبة

الموقع يستخدم المشروع `ikill-4e337`، لكن إعداداته الموجودة في الريبو **خاصة بتطبيق ويب**؛ لا تصلح لاختراع معرّفات Android/iOS منها.

1. افتح Firebase Console للمشروع نفسه بحسابك المصرح له.
2. أضف تطبيق Android باسم الحزمة `net.ikill.app` وحمّل `google-services.json`.
3. أضف تطبيق iOS بمعرّف Bundle `net.ikill.app` وحمّل `GoogleService-Info.plist`.
4. من مجلد التطبيق شغّل، مع استبدال المسارات بمسارات ملفاتك:

```sh
python3 tool/configure_firebase.py \
  --android /path/to/google-services.json \
  --ios /path/to/GoogleService-Info.plist
flutter run --dart-define-from-file=firebase_build.json
```

الأداة تتحقق من اسم المشروع ومعرّفات التطبيقات وتولّد ملف إعداد محلي. يستخدم التطبيق `FirebaseOptions` مباشرة؛ **لا تحتاج لنقل ملف plist إلى Xcode أو إضافة Google Services plugin** لهذا المسار. مرّر الملف نفسه لكل أوامر البناء. لا تنشر `firebase_build.json` في مستودع عام. لا تستخدم web appId لتطبيق موبايل.

لم يتم إنشاء تطبيقات في Firebase Console أو تغيير قواعد المشروع أو نشر أي شيء. السكربت لا يتصل بالخادم ولا يعدل البيانات.

### البيانات المتوافقة مع الموقع

- `contact_submissions`: الحقول `name`, `phone`, `email`, `address`, `service`, `message`, `timestamp` بنفس صيغة الموقع. التأكيد لا يظهر إلا بعد نجاح كتابة Firestore. عند الفشل تبقى بيانات النموذج ولا يُعاد الإرسال آلياً.
- `branches`: قراءة الفروع النشطة، وإدارة الأسماء العربية/الإنجليزية والدول والحالة والهاتف.
- `site_settings/global`: قراءة إحصائيات الرئيسية، وتعديل إعدادات الموقع من لوحة الإدارة.
- `page_views`: عرض السجلات الموجودة للإدارة. التطبيق **لا يجمع زيارات جديدة تلقائياً**.
- Firebase Authentication: دخول الإدارة بالبريد وكلمة المرور، وتسجيل الخروج وتغيير كلمة المرور مع إعادة التحقق.

**تنبيه أمني مهم:** قواعد الموقع الحالية تعتبر أي مستخدم مسجل الدخول مخولاً لقراءة/تعديل/حذف بيانات الإدارة. التطبيق لا يضيف تسجيل حسابات جديداً، لكن يجب على مسؤول المشروع مراجعة الصلاحيات واستخدام أدوار إدارة حقيقية قبل النشر العام. لم نغير قواعد الريبو أو الخلفية.

## البناء

بدون اتصال Firebase يمكن حذف وسيط `--dart-define-from-file` لاختبار المحتوى فقط.

```sh
flutter analyze --no-fatal-infos --no-fatal-warnings
flutter test
flutter build apk --debug --dart-define-from-file=firebase_build.json
```

APK التجربة يوجد في `build/app/outputs/flutter-apk/app-debug.apk` بعد نجاح البناء.

لنسخة Android المنشورة: أضف مفتاح توقيع release خاصاً بك إلى Gradle ثم:

```sh
flutter build appbundle --release --dart-define-from-file=firebase_build.json
```

إعداد release الحالي يستخدم توقيع debug الافتراضي لقالب Flutter، **ليس صالحاً للنشر في المتجر**. لا ترسل مفاتيح التوقيع في الدردشة.

على macOS:

```sh
flutter build ios --release --no-codesign --dart-define-from-file=firebase_build.json
open ios/Runner.xcworkspace
```

اختر فريق Apple Developer واضبط Signing & Capabilities، ثم Archive/Distribute من Xcode. إنشاء IPA قابل للتثبيت يحتاج توقيع Apple صالحاً؛ ملف Runner.app غير الموقّع ليس IPA قابلاً للتثبيت على هاتف.

## نطاق النقل وحدوده

- الرئيسية والخدمات والقطاعات ومن نحن والفروع والتواصل والخصوصية والشروط بواجهات أصلية.
- اتجاه RTL/LTR، تبديل العربية/الإنجليزية والمظهر الداكن وحفظهما محلياً.
- صور الشركاء في شريط تمرير أصلي، وأيقونات SVG محلية، واتصال وبريد وواتساب وخرائط عبر تطبيقات الجهاز.
- نموذج يتضمن التحقق من الحقول وموافقة الخصوصية ومراجعة قبل الإرسال وحالات انتظار/نجاح/فشل.
- لوحة إدارة أصلية للطلبات وتفاصيلها والبحث والحذف والفروع والإعدادات وعرض الزيارات وتغيير كلمة المرور.
- إعادة بناء مناسبة للموبايل وليست نسخة pixel-perfect من CSS. تأثيرات الويب والجزيئات وحركات الصفحة لم تُنقل حرفياً. الخريطة تُفتح خارجياً بدلاً من iframe.
- الترجمات الأصلية للموقع منقولة؛ النص الذي ليس له ترجمة أصلية، بما فيه أجزاء من الصفحات القانونية، يبقى بالعربية بدلاً من اختراع نص قانوني بديل.
- بعض أرقام/نصوص الموقع وعلاقات الشركات منقولة كما وردت، وليست تحققاً مستقلاً من صحتها. راجعها قبل إطلاق التطبيق.
- يلزم مراجعة سياسة الخصوصية لتناسب الموبايل وإقرارات Google Play وApp Store قبل الإطلاق.

**حالة التسليم:** كود مصدر ومشروعات المنصتين، وليس APK/IPA مختبراً أو تطبيقاً منشوراً. Flutter SDK وXcode غير متاحين في بيئة الإنشاء، لذلك لم يُنفَّذ `flutter analyze` أو `flutter test` أو بناء المنصتين هنا. انظر `VERIFICATION.md` للتفاصيل.
